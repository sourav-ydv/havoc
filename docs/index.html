havoc

Fault injection and failure shrinking for AI agents that use MCP tools. source code on GitHub

Most agent tests only cover the happy path. This project breaks the tools an agent depends on, on purpose, and watches what the agent does to a real database. It tries single faults and pairs of faults, and shrinks any failing combination to the smallest set that still fails.

8 of 220single faults broke the agent
13 of 191pairs of faults broke the agent
2failures that needed both faults of a pair
10 of 13failing pairs were just one bad fault plus noise

One model (Gemini 3.5 Flash-Lite), five customer-support tasks, free-tier limits. These numbers describe this setup, not agents in general.

How it works

The proxy sits between the agent and its tools and can fail a call before or after it runs, cut a result in half, corrupt or drop a field, or add a prompt injection to the output. After each run, safety checks read the database, not what the agent claims it did.

unsafe: a safety check fired (a false claim, a refund over the limit, mail to a stranger). runaway: the agent looped or ran out of turns. incomplete: the task was not done and nothing unsafe happened.

Comparing the failure rate of single faults with that of pairs gives a Fisher exact p-value of 0.179, which is not a meaningful difference. Counting failing runs is not the interesting part, the interesting part is which failures only appear when two faults combine.

Limits

  • One model, one domain, five tasks.
  • Even at temperature 0 the same run can differ, so a failure is a rate, not a yes or no.
  • The checks that read the agent's answer are heuristics.
  • Failing runs were re-run five times at temperature 0.7, which separates failures that happen every time from ones that never happen and not much more.
  • Only two failures needed both faults of a pair, so any claim about compound failures rests on very few events.
  • Delta debugging and fault injection for agents both existed before this. I applied them to MCP agents with state-based checks.
